A. Thông Tin Chung Về Khóa Học

1. Mục tiêu khóa học

Sau khi hoàn thành chuỗi 8 buổi học thực chiến này, sinh viên sẽ làm chủ được các năng lực cốt lõi sau:

  • Hiểu bản chất: Định vị được Spring Boot trong hệ sinh thái Java; hiểu rõ lý do doanh nghiệp dịch chuyển sang Spring Boot thay vì Spring MVC truyền thống.
  • Khởi tạo & Cấu hình: Tự cấu hình, tổ chức quản lý dự án chuẩn thông qua Maven.
  • Kiến trúc ứng dụng: Áp dụng thuần thục kiến trúc phân tầng 3 lớp (Controller – Service – Repository) khi viết mã nguồn.
  • Thao tác dữ liệu: Làm chủ công nghệ ORM, kết nối kết xuất dữ liệu MySQL thông qua Spring Data JPA một cách tự động.
  • Hoàn thiện API chuẩn: Xây dựng hệ thống REST API tích hợp đầy đủ tính năng validation (kiểm tra dữ liệu rác) và xử lý ngoại lệ tập trung.
  • Đóng gói & Phát hành: Đóng gói ứng dụng thành tệp thực thi độc lập, ảo hóa môi trường qua Docker và deploy thành công lên internet thực tế.

2. Yêu cầu đầu vào

  • Đã hoàn thành môn Lập trình Java cơ bản (nắm chắc lập trình hướng đối tượng OOP, Exception Handling, Collections Framework, Generic, Lambda và Stream API).
  • Đã làm quen với hệ quản trị cơ sở dữ liệu quan hệ và ngôn ngữ SQL ở mức cơ bản (các lệnh SELECT, INSERT, UPDATE, DELETE và câu lệnh truy vấn JOIN).

3. Công cụ và phần mềm chuẩn bị

  • JDK 17 hoặc JDK 21 (LTS) làm môi trường biên dịch lõi.
  • IntelliJ IDEA Community Edition (hoặc bản Ultimate) hoặc Eclipse/Spring Tool Suite.
  • Maven (Được tích hợp sẵn đi kèm cùng IDE, không yêu cầu cài đặt riêng độc lập).
  • MySQL Server 8.x kết hợp giao diện trực quan MySQL Workbench hoặc DBeaver.
  • Postman (hoặc Insomnia) phục vụ công tác gửi gói request kiểm thử hệ thống API.
  • Git và tài khoản cá nhân trên nền tảng GitHub để quản lý toàn bộ kho lưu trữ source code.

Buổi 2: REST Controller Cơ Bản & Thao Tác Dữ Liệu Tạm Thời

2.1 Tóm tắt Lý thuyết & Kiến thức Cốt lõi

RESTful API thiết lập thiết kế định vị tài nguyên bằng danh từ số nhiều quy ước công khai và thực hiện thao tác tác động trực tiếp thông qua 4 giao thức HTTP chính xác: GET (Đọc dữ liệu), POST (Khởi tạo mới), PUT (Sửa đổi toàn bộ), và DELETE (Xóa bỏ).

2.2 Hướng dẫn thực hành từng bước (Step-by-Step)

Bước 1: Thiết kế mô hình lớp thực thể lưu trữ đối tượng (Model)

Tạo một package mới mang tên com.fpoly.lab.model. Khởi tạo tệp tin Product.java ứng dụng Lombok:

Java
package com.fpoly.lab.model;

import lombok.AllArgsConstructor;
import lombok.Data;
import lombok.NoArgsConstructor;

@Data
@NoArgsConstructor
@AllArgsConstructor
public class Product {
    private Long id;
    private String name;
    private Double price;
}
Bước 2: Triển khai ProductController xử lý API tuần hoàn CRUD

Tạo một Class Java mới mang tên ProductController.java đặt trong gói controller:

Java
package com.fpoly.lab.controller;

import com.fpoly.lab.model.Product;
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;
import java.util.ArrayList;
import java.util.List;

@RestController
@RequestMapping("/api/products")
public class ProductController {

    private final List productList = new ArrayList<>();

    public ProductController() {
        productList.add(new Product(1L, "Laptop Acer Nitro", 18500000.0));
        productList.add(new Product(2L, "Chuột Logitech G102", 400000.0));
    }

    @GetMapping
    public ResponseEntity> getAllProducts() {
        return ResponseEntity.ok(productList);
    }

    @GetMapping("/{id}")
    public ResponseEntity getProductById(@PathVariable Long id) {
        for (Product p : productList) {
            if (p.getId().equals(id)) return ResponseEntity.ok(p);
        }
        return ResponseEntity.status(HttpStatus.NOT_FOUND).body("Không tìm thấy sản phẩm mã ID: " + id);
    }

    @PostMapping
    public ResponseEntity createProduct(@RequestBody Product newProduct) {
        productList.add(newProduct);
        return ResponseEntity.status(HttpStatus.CREATED).body(newProduct);
    }

    @PutMapping("/{id}")
    public ResponseEntity updateProduct(@PathVariable Long id, @RequestBody Product updatedProduct) {
        for (Product p : productList) {
            if (p.getId().equals(id)) {
                p.setName(updatedProduct.getName());
                p.setPrice(updatedProduct.getPrice());
                return ResponseEntity.ok(p);
            }
        }
        return ResponseEntity.status(HttpStatus.NOT_FOUND).body("Thất bại. Không thấy ID.");
    }

    @DeleteMapping("/{id}")
    public ResponseEntity deleteProduct(@PathVariable Long id) {
        boolean removed = productList.removeIf(p -> p.getId().equals(id));
        if (removed) return ResponseEntity.ok("Xóa bỏ thành công sản phẩm ID: " + id);
        return ResponseEntity.status(HttpStatus.NOT_FOUND).body("Xóa thất bại.");
    }
}
Bước 3: Hướng dẫn cấu hình kiểm thử dữ liệu qua phần mềm Postman

JSON

Bấm chọn nút Send kiểm tra mã trạng thái góc màn hình phản hồi chuẩn 201 Created.

Bài tập rèn luyện nâng cao về nhà

  • Bổ sung endpoint GET /api/products/statistics trả về thống kê: tổng số, giá trung bình, cao nhất, thấp nhất.
  • Tạo collection Postman lưu lại các request đã test, export ra file JSON và đẩy lên GitHub.

Tiêu chí đánh giá

Buổi 3: Dependency Injection & Kiến Trúc Thiết Kế Phân Tầng 3 Lớp

3.1 Tóm tắt Lý thuyết & Kiến thức Cốt lõi

Việc viết dồn toàn bộ mã nguồn xử lý logic nghiệp vụ và lưu trữ vào duy nhất file Controller vi phạm nghiêm trọng nguyên lý đơn nhiệm diện rộng. Kiến trúc 3-Tier Architecture phân rã tách biệt dự án thành các lớp độc lập: Controller (Giao tiếp), Service (Thuật toán Nghiệp vụ), và Repository (Truy xuất Kho dữ liệu).

3.2 Hướng dẫn thực hành từng bước (Step-by-Step)

Bước 1: Triển khai thiết kế cô lập tầng quản lý dữ liệu Repository

Tạo một gói package mới mang tên com.fpoly.lab.repository. Khởi tạo một Class Java mang tên ProductRepository.java:

Java
package com.fpoly.lab.repository;

import com.fpoly.lab.model.Product;
import org.springframework.stereotype.Repository;
import java.util.ArrayList;
import java.util.List;
import java.util.Optional;

@Repository // Đăng ký Class này thành một Spring Bean chịu trách nhiệm quản lý kho dữ liệu của hệ thống
public class ProductRepository {
    private final List list = new ArrayList<>();

    public ProductRepository() {
        list.add(new Product(1L, "Sách Java core", 150000.0));
    }

    public List findAll() { return list; }
    public Optional findById(Long id) {
        return list.stream().filter(p -> p.getId().equals(id)).findFirst();
    }
    public void save(Product product) { list.add(product); }
}
Bước 2: Triển khai thiết kế tầng quản trị trung gian thuật toán nghiệp vụ Service

Tạo một package mới mang tên com.fpoly.lab.service. Khởi tạo một lớp Java mang tên ProductService.java:

Java
package com.fpoly.lab.service;

import com.fpoly.lab.model.Product;
import com.fpoly.lab.repository.ProductRepository;
import org.springframework.stereotype.Service;
import java.util.List;

@Service // Đăng ký Class này đóng vai trò tầng chứa đựng logic tính toán nghiệp vụ
public class ProductService {

    private final ProductRepository productRepository;

    // Kỹ thuật Constructor Injection bắt buộc giúp tự động nạp (tiêm) Bean phụ thuộc từ IoC Container
    public ProductService(ProductRepository productRepository) {
        this.productRepository = productRepository;
    }

    public List getAllProducts() { return productRepository.findAll(); }

    public Product addProduct(Product product) {
        if (product.getPrice() < 0) {
            throw new IllegalArgumentException("Lỗi: Giá sản phẩm bán ra thị trường không được phép mang giá trị âm");
        }
        productRepository.save(product);
        return product;
    }
}
Bước 3: Cấu trúc lại Controller phiên bản mới gọi liên kết qua Service

Tạo một Class Java điều phối nâng cấp mang tên `ProductControllerV2.java` nằm trong gói `controller`:

Java
package com.fpoly.lab.controller;

import com.fpoly.lab.model.Product;
import com.fpoly.lab.service.ProductService;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;
import java.util.List;

@RestController
@RequestMapping("/v2/products") // Quy ước phân rã phiên bản API nâng cấp mang tiền tố mới /v2
public class ProductControllerV2 {

    private final ProductService productService;

    public ProductControllerV2(ProductService productService) {
        this.productService = productService;
    }

    @GetMapping
    public ResponseEntity> getProducts() {
        return ResponseEntity.ok(productService.getAllProducts());
    }

    @PostMapping
    public ResponseEntity saveProduct(@RequestBody Product product) {
        return ResponseEntity.ok(productService.addProduct(product));
    }
}

Bài tập rèn luyện nâng cao về nhà

  • Hoàn thiện refactor project Product 3 lớp đầy đủ.
  • Viết tối thiểu 3 unit test cho ProductService: test khi tìm thấy sản phẩm, khi không tìm thấy, khi thêm mới hợp lệ.
  • Vẽ sơ đồ class diagram đơn giản (có thể vẽ tay rồi chụp ảnh) thể hiện quan hệ giữa 3 tầng.

Tiêu chí đánh giá

  • Project chia đúng 3 tầng, package gọn gàng (4 điểm).
  • Sử dụng constructor injection (không dùng @Autowired field) (2 điểm).
  • Có ít nhất 3 unit test pass thành công (3 điểm).
  • Có sơ đồ class diagram đính kèm (1 điểm).

Buổi 4: Kết Nối Cơ Sở Dữ Liệu Thật Với Spring Data JPA (P1)

4.1 Tóm tắt Lý thuyết & Kiến thức Cốt lõi

Spring Data JPA là giải pháp công nghệ bọc trừu tượng (Wrapper) nằm phía trên JPA tiêu chuẩn, ứng dụng sức mạnh của Hibernate framework để triển khai kỹ nghệ ánh xạ thực thể ORM (Object-Relational Mapping) thông minh, tự động chuyển đổi cấu trúc Class Java thành định dạng bảng lưu trữ quan hệ tương thích dưới MySQL.

4.2 Hướng dẫn thực hành từng bước (Step-by-Step)

Bước 1: Chuẩn bị cơ sở dữ liệu trống trên hệ quản trị MySQL

Mở ứng dụng MySQL Workbench truy cập máy chủ phòng máy, tạo cơ sở dữ liệu mới hỗ trợ font tiếng Việt:

SQL
CREATE DATABASE fpoly_spring_core CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
Bước 2: Bổ sung Driver kết nối dữ liệu vào file điều phối quản lý tài nguyên pom.xml

Chèn thêm đoạn mã cấu hình dependencies sau vào bên trong tệp tin pom.xml:

XML
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-jpa</artifactId>
</dependency>
<dependency>
    <groupId>com.mysql</groupId>
    <artifactId>mysql-connector-j</artifactId>
    <scope>runtime</scope>
</dependency>

*Chú ý bắt buộc:* Nhấp chọn nút lệnh biểu tượng vòng xoay **Reload All Maven Projects** ở góc phải màn hình IntelliJ để ép buộc hệ thống tải file thư viện về.

Bước 3: Định cấu hình khai báo chuỗi liên kết DataSource liên thông

Bước 3: Viết bộ xử lý thu gom và cấu trúc lại mã lỗi toàn cục tập trung

Tạo một gói package mới mang tên com.fpoly.lab.exception. Khởi tạo một lớp Java mang tên GlobalExceptionHandler.java đảm nhận nhiệm vụ chuyển đổi mã lỗi mặc định:

Java
package com.fpoly.lab.exception;

import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.validation.FieldError;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;
import java.util.HashMap;
import java.util.Map;

@RestControllerAdvice // Bộ chặn lắng nghe thụ động toàn diện lỗi phát sinh từ các phân tầng dự án đưa lên
public class GlobalExceptionHandler {

    // Hàm chuyên biệt bóc tách thông tin khi màng lọc kiểm tra Validation đầu vào thất bại
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity> handleValidationExceptions(MethodArgumentNotValidException ex) {
        Map errors = new HashMap<>();

        ex.getBindingResult().getAllErrors().forEach((error) -> {
            String fieldName = ((FieldError) error).getField();
            String errorMessage = error.getDefaultMessage();
            errors.put(fieldName, errorMessage);
        });

        return ResponseEntity.status(HttpStatus.BAD_REQUEST).body(errors);
    }
}

Đừng quên chèn thêm từ khóa Annotation kích hoạt @Valid đứng ngay trước tham số @RequestBody Product product trong hàm lưu trữ tại lớp Controller để kích hoạt luật chặn bảo vệ.

  • Test ít nhất 5 trường hợp lỗi khác nhau qua Postman và lưu vào collection.

Tiêu chí đánh giá

Bước 2: Áp dụng quy trình Mapping chuyển đổi thủ công kết hợp ghi Log hệ thống

Khởi tạo một lớp Java dịch vụ xử lý riêng biệt mang tên ProductBackupService.java nằm trọn trong gói package service:

Java
package com.fpoly.lab.service;

import com.fpoly.lab.dto.ProductDTO;
import com.fpoly.lab.model.Product;
import com.fpoly.lab.repository.ProductDbRepository;
import lombok.extern.slf4j.Slf4j;
import org.springframework.stereotype.Service;

@Service
@Slf4j // Tự động nạp tích hợp biến Logger mang tên định danh chuẩn "log" của thư viện SLF4J
public class ProductBackupService {

    private final ProductDbRepository repository;

    public ProductBackupService(ProductDbRepository repository) {
        this.repository = repository;
    }

    public ProductDTO getProductDtoInfo(Long id) {
        log.info("Hệ thống bắt đầu kích hoạt lệnh truy vấn tìm kiếm sản phẩm mang mã số ID: {}", id);
        
        Product product = repository.findById(id)
                .orElseThrow(() -> {
                    log.error("Lỗi nghiêm trọng: Không quét thấy bất kỳ bản ghi nào trùng khớp mã ID: {}", id);
                    return new RuntimeException("Sản phẩm yêu cầu không tồn tại trên hệ thống DB.");
                });

        // Quy trình thực hiện chuyển đổi ánh xạ tay Mapping từ đối tượng Entity sang mô hình bọc bảo mật DTO
        ProductDTO dto = new ProductDTO();
        dto.setName(product.getName());
        dto.setPrice(product.getPrice());
        
        log.info("Quy trình đóng gói bọc chuyển đổi dữ liệu sang DTO hoàn tất thành công cho sản phẩm: {}", dto.getName());
        return dto;
    }
}

Bài tập rèn luyện nâng cao về nhà

  • Bổ sung log ở tất cả các action CRUD chính.
  • Tạo profile prod với cấu hình MySQL khác và logging level WARN.
  • Test chạy với profile dev và profile prod, chụp ảnh log để chứng minh.

Tiêu chí đánh giá

  • DTO được tách đầy đủ cho ít nhất 2 entity (3 điểm).
  • Mapping hoạt động đúng (bằng tay hoặc MapStruct) (2 điểm).
  • Có log ở các action chính, ghi được ra file (3 điểm).

  • Đề 2 - Quản lý Sinh viên - Khóa học: Sinh viên, Lớp, Khóa học. Sinh viên có thể đăng ký nhiều khóa học, có điểm số.
  • Đề 3 - Blog cá nhân: Bài viết, Chuyên mục, Tag, Bình luận. Có API tìm kiếm theo tag, lọc theo chuyên mục.
  • Đề 4 - Quản lý sản phẩm: Sản phẩm, Danh mục, Đơn hàng, Khách hàng. Có thống kê doanh thu cơ bản.

Yêu cầu chung: Có ít nhất 4 entity với quan hệ rõ ràng; Đầy đủ CRUD; Có validation, exception handling; Phân trang ít nhất 1 API; Có chia DTO; Có Log; Có README.md trên GitHub và có Postman Collection đi kèm.

8.2 Hướng dẫn Build & Deploy (Step-by-Step)

Bước 1: Thực hiện lệnh đóng gói ứng dụng bằng bộ công cụ điều khiển Maven Lifecycle

Nhìn sang thanh công cụ dọc bên phải màn hình IntelliJ IDEA, click chuột trái mở rộng tab quản lý công cụ **Maven** → Chọn mở thư mục con **Lifecycle** → Thực hiện kích hoạt nhấp đúp chuột liên tiếp tuần tự vào hai lệnh điều khiển hành động cốt lõi sau:

  1. Nhấp đúp chuột vào tiến trình lệnh clean (Hệ thống quét dọn xóa sạch các tệp tin lưu cache thừa cũ).
  2. Nhấp đúp chuột vào tiến trình lệnh package (Hệ thống chạy tự động kiểm thử biên dịch và thực hiện nén dự án).

Theo dõi luồng log chạy ra đạt chữ thông báo thành công màu xanh: [INFO] BUILD SUCCESS. Truy cập thư mục con vừa tự động sinh ra mang tên là /target nằm ở cây thư mục dự án xác nhận tệp tin cứng: sof3022-lab-0.0.1-SNAPSHOT.jar.

Bước 2: Thiết lập file cấu hình đóng gói Container ảo hóa Dockerfile

Tại khu vực thư mục gốc ngoài cùng cao nhất của dự án (Vị trí nằm ngang hàng so với file pom.xml), click chuột phải chọn khởi tạo file mới đặt tên chính xác hoàn toàn là `Dockerfile`. Viết nội dung thiết lập chi tiết sau:

Dockerfile
# Bước 1: Sử dụng cấu trúc Base Image chứa môi trường chạy Java OpenJDK 17 xây dựng trên nhân Linux rút gọn
FROM eclipse-temurin:17-jdk-alpine

# Bước 2: Thiết lập khai báo đường dẫn thư mục làm việc chính thức bên trong máy chủ ảo Container
WORKDIR /app

# Bước 3: Thực hiện sao chép file cứng .jar từ máy local target vào bên trong cấu trúc máy chủ ảo
COPY target/sof3022-lab-0.0.1-SNAPSHOT.jar app.jar

# Bước 4: Cấu hình lệnh ép buộc hệ thống kích hoạt khởi chạy file jar độc lập ngay khi bật container
ENTRYPOINT ["java", "-jar", "app.jar"]

# Bước 5: Khai báo mở cổng mạng giao tiếp ảo tương thích cấu hình properties của dự án
EXPOSE 8081
Bước 3: Đẩy mã nguồn lên nền tảng đám mây GitHub và kết nối thực thi Deploy trực tuyến

Đẩy toàn bộ dự án lên một Repository cá nhân trạng thái công khai thiết lập trên trang GitHub cá nhân. Sử dụng trình duyệt truy cập vào hệ thống đám mây quản lý Render.com, tiến hành chọn liên kết tài khoản GitHub cá nhân và nhấp chọn dòng lệnh khởi tạo dịch vụ **New Web Service**.

Hệ thống đám mây sẽ tự động phát hiện tệp tin `Dockerfile` có sẵn trong dự án để tự cấu hình quy trình nạp môi trường cách ly tự động hoàn toàn. Chờ đợi tiến trình cài đặt và biên dịch tự động diễn ra trong vòng 2-3 phút, Render sẽ trực tiếp cấp phát một đường link liên kết URL dạng công khai chạy trực tuyến (Live) ổn định thực tế trên internet: https://tên-dự-án-của-bạn.onrender.com/v2/products.

  • Spring Security và JWT: Xác thực và phân quyền, bảo mật REST API.
  • Testing nâng cao: Integration test với @SpringBootTest, TestContainers.
  • Spring Boot Actuator & Monitoring: Giám sát tình trạng ứng dụng (Health check, metrics).
  • Caching: Tối ưu hóa hiệu năng truy vấn với Redis.
  • Spring Cloud & Microservices: Service discovery, API Gateway, Message Queue (RabbitMQ/Kafka).
  • CI/CD: Tự động hóa build và deploy bằng GitHub Actions / GitLab CI.
