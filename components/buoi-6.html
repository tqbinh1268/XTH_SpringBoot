Buổi 6: Khai Phá Màng Lọc Validation Đầu Vào & Bộ Xử Lý Lỗi Toàn Cục Tập Trung

6.1 Tóm tắt Lý thuyết & Kiến thức Cốt lõi

Nguyên tắc vàng của lập trình viên: "Không bao giờ tin tưởng hoàn toàn vào dữ liệu do phía Client gửi lên". Việc tích hợp bộ thư viện Bean Validation hỗ trợ định cấu hình màng lọc chặt chẽ ngay tại lớp Controller, kết hợp bộ xử lý ngoại lệ tập trung `@RestControllerAdvice` giúp bao bọc an toàn và chuyên nghiệp hóa hệ thống phản hồi thông điệp lỗi.

6.2 Hướng dẫn thực hành từng bước (Step-by-Step)

Bước 1: Khai báo nạp thư viện kiểm tra dữ liệu đầu vào vào file pom.xml
XML
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-validation</artifactId>
</dependency>
Bước 2: Thiết lập khai báo các luật ràng buộc trực tiếp trên Entity thuộc tính

Cập nhật tệp tin mô hình lớp dữ liệu ProductDb.java chèn thêm điều kiện bọc lỗi:

Java
public class ProductDb {
    private Long id;

    @NotBlank(message = "Lỗi: Trường tên sản phẩm không được phép để rỗng hoặc nhập khoảng trắng đơn thuần")
    @Size(min = 3, max = 50, message = "Lỗi: Độ dài của tên sản phẩm bắt buộc phải nằm trong giới hạn từ 3 đến 50 ký tự")
    private String name;

    @NotNull(message = "Lỗi: Giá của sản phẩm yêu cầu bắt buộc phải thực hiện nhập thông tin")
    @Min(value = 1000, message = "Lỗi: Mức định giá của sản phẩm tối thiểu phải đạt mốc giá trị từ 1000 VNĐ trở lên")
    private Double price;
}
Bước 3: Viết bộ xử lý thu gom và cấu trúc lại mã lỗi toàn cục tập trung

Tạo một gói package mới mang tên com.fpoly.lab.exception. Khởi tạo một lớp Java mang tên GlobalExceptionHandler.java đảm nhận nhiệm vụ chuyển đổi mã lỗi mặc định:

Java
package com.fpoly.lab.exception;

import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.validation.FieldError;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;
import java.util.HashMap;
import java.util.Map;

@RestControllerAdvice // Bộ chặn lắng nghe thụ động toàn diện lỗi phát sinh từ các phân tầng dự án đưa lên
public class GlobalExceptionHandler {

    // Hàm chuyên biệt bóc tách thông tin khi màng lọc kiểm tra Validation đầu vào thất bại
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity> handleValidationExceptions(MethodArgumentNotValidException ex) {
        Map errors = new HashMap<>();

        ex.getBindingResult().getAllErrors().forEach((error) -> {
            String fieldName = ((FieldError) error).getField();
            String errorMessage = error.getDefaultMessage();
            errors.put(fieldName, errorMessage);
        });

        return ResponseEntity.status(HttpStatus.BAD_REQUEST).body(errors);
    }
}

Đừng quên chèn thêm từ khóa Annotation kích hoạt @Valid đứng ngay trước tham số @RequestBody ProductDb product trong hàm lưu trữ tại lớp ProductDbController để kích hoạt luật chặn bảo vệ.

Bài tập rèn luyện nâng cao về nhà

  • Bổ sung validation cho Request cập nhật (có thể khác với Request tạo mới).
  • Tạo custom annotation @ValidPhoneNumber cho số điện thoại Việt Nam (10 số, bắt đầu bằng 0).
  • Test ít nhất 5 trường hợp lỗi khác nhau qua Postman và lưu vào collection.

Tiêu chí đánh giá

  • Validation đầy đủ trên 4 trường yêu cầu (3 điểm).
  • GlobalExceptionHandler hoạt động, trả response chuẩn (3 điểm).
  • Custom annotation hoạt động đúng (2 điểm).
  • Postman collection có đủ ca lỗi (2 điểm).
